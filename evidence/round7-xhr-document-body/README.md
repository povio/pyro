# XMLHttpRequest document bodies and charset handling

XHR serializes an HTML Document using HTML fragment serialization and an XML Document using XML serialization. Both are sent as UTF-8. The default MIME types are text/html;charset=UTF-8 and application/xml;charset=UTF-8 respectively. A caller-supplied Content-Type is retained exactly unless a Document or USVString needs an explicit non-UTF-8 charset corrected. That case reparses and serializes the MIME type with a UTF-8 parameter. Blob, BufferSource and URLSearchParams retain their own handling. [Source](https://github.com/povio/pyro/commit/c8a9e335f3126d800c7d150674df5119d79c66f8) · [XHR send algorithm](https://xhr.spec.whatwg.org/#the-send()-method)

The 19 selected WPT URLs registered 107 named results on each browser. Implementation-owner measurements were 70 named passes and 13 fully passing pages on bd247dd67babbff29fb87017f9a6bededfb68ea2, 90 and 17 on c8a9e335f3126d800c7d150674df5119d79c66f8, and 87 and 16 on Chrome stable 158.0.8127.37. Raw differences were 20 gained and zero lost; all pages completed with OK harness status. No names were added or missing. Nineteen gains exercise the changed behavior: 13 document-body/MIME assertions and six string charset assertions. Five of the six charset gains are WPT cases Chrome also fails. The twentieth observed gain, a 304 GET redirect, takes the unchanged bodyless path and is recorded separately. Nine Chrome-only names remain, all on send-redirect.htm.

The implementation owner measured each browser against a local HTTP echo server. The server recorded actual request bytes and headers for ten body/charset cases plus 72 sequential XHRs on one reused instance. All 82 requests completed on each browser. The XML and HTML document payloads agree with Chrome on the wire, including non-ASCII Unicode characters, doctype, void elements and escaped text. The Blob, byte-view and URLSearchParams controls retain their caller-specified charset. The byte-string header parameter café survives MIME serialization. Chromium differs on formatting and duplicate parameters in the author-charset cases; the WPT expectations and exact wire values are retained.

The frozen single-byte XHR page initiates 168 asynchronous sends synchronously during registration. The 64-pending-request limit accounted for its first reported rejection after 64 successes. The implementation removes completed jobs before load callbacks, and the sequential probe confirmed that completed requests release capacity. The single-byte iframe cohort recorded 128 named passes before timing out, and the unsupported-label cohort schedules 158 frames with failures among the last 30. The implementation retains its 128-child-frame limit. These coverage observations are separate from the body change. The responseXML document-properties page aborted during registration because HTMLAllCollection was unavailable.

## Reproduction

The shared combined-QA executable supplied the exact baseline. Only the candidate was built for this batch, with one Cargo job. Both use CI arm64 JSC 0e0dd7038a7a-6f4649e395e0. The WPT pin was a421f2fea5eb7f91e0db399e44b0fb0779ee1603 and the manifest SHA-256 was 34a67512a84d43630f7adbecebd4378df5f410446591015cc6a20a3034e02819. Selection members are ordinary, eligible URLs on that manifest; none were in the frozen holds. WPT used one job, fresh page contexts, wptserve, HTTP/2, testdriver and 800×600 DPR 1 for each browser, serially. Chrome used the signed macOS arm64 stable profile and Playwright 1.65.1. Independent source review on the frozen commit covered serialization, charset rewriting, other body types and the send/generation recheck.

```sh
bun bench/wpt/run-no-native-retry.mjs --wpt "$WPT" --kind testharness --dirs non-css --jobs 1 \
  --server wptserve --testdriver --http2 --generated-globals "$MANIFEST" --manifest-inventory \
  --measure-reviewed-skips --tests urls.json --bin "$LABEL=$BIN" --out "$OUT"
```

named.json records URL, original name, duplicate occurrence, baseline status, candidate status and local Chrome 158 status. pages.json records the same browsers' page and harness statuses and fully-passing flags. Null means unobserved. wire-summary.json and wire-probes.tar.gz include the ten controls and all sequential-request receipts.

Independent runtime QA reran the candidate and confirmed all 107 named statuses (+20/−0) against the shared baseline and signed Chrome reference. Fourteen gained names pass Chrome and six fail there. Its direct echo measurements confirmed 82/82 completed sends and body-byte agreement with Chrome on all 82 candidate requests. Complete method, header and byte agreement with Chrome rose from 76/82 to 78/82. Three residual wire differences are the XML/string author Content-Type formatting described above; the fourth is URLSearchParams with a caller charset, which LP preserves and Chrome rewrites. independent-qa.json records the independent receipt hashes separately from the implementation-owner files.
