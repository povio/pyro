# Native Wasm JS metadata controls

Seven additional pinned WPT URLs tested ordinary native object metadata without compiling or executing a module. The exact aa0268b479a6b463da16910b4b743cf38901d962 build and Chrome stable 158.0.8127.37 both completed all seven pages with 16/16 named passes, no restarts and no watchdog kills. The original four-job manifest-first WPT runner used the verified Chrome launcher, a fresh context per page, WPT server, HTTPS/HTTP2 support, testdriver, generated globals and an 800×600 viewport. Source pin a421f2fea5eb7f91e0db399e44b0fb0779ee1603. These rows are a separate addendum with no changes to the shared reference plan, code, expectations or runtime options.

The immutable scope comprised memory/table/tag toStringTag descriptors and class strings in Window and dedicated worker, plus the worker table-length getter. The pinned toString tests create only a zero-size memory, zero-length table, or empty-parameter tag. The length page creates a two-element table and tests accessors. Every listed source was read, each source blob matched the pinned manifest, and all seven URLs had independently complete/fully passing earlier base, intermediate and Chrome records in shards without native restarts. Their sole prior withholding reason was the blanket Wasm runtime hold. Per-URL evidence is in provenance.json. Actual or ambiguous native-risk URLs remain withheld, including both Global type-reflection variants.

A separate no-construction diagnostic inspected own descriptors for type on the existing Global, Table, Memory and Tag prototypes and the presence of WebAssembly.Function. Each was absent in both engines, in Window and dedicated worker. In the pinned WebKit source the four native prototypes and module import/export type descriptors check the same useWasmJSTypes engine option. WasmJSTypesEnabled in Source/WTF/Scripts/Preferences/UnifiedWebPreferences.yaml is testable, false by default and a WebKit web-process preference. The standalone JSC C API does not expose a documented per-realm setter or a type-descriptor extraction API for these objects. No process option was enabled. The probe therefore establishes no actual reflection deficit versus Chrome stable 158 and supports no production change.

The original Wasm manifest still contains 616 URLs (538 browser URLs, 78 jsshell). These seven are disjoint from the immutable shared selection and the five storage-only addendum URLs. The seven pairs are fresh measurements only on aa0268b47 / Chrome 158, not proof of execution, streaming, or broader Wasm parity.
