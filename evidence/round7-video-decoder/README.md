## Runtime contract and limits

Secure Window and dedicated-worker realms get VideoDecoder. Dedicated worker exposure derives from the creator's security state and the trustworthiness of the script URL, including nested workers. A per-decoder control queue orders configuration, input, output, flush, reset and close, emits trusted dequeue events and rejects pending flushes on reset. Decoding uses rav1d and OpenH264 already shipped with the browser. Native work is performed during scheduled codec tasks on the owning realm thread; a long running decode can delay other work on that thread.

The packet path supports AV1 Main profile with 8- or 10-bit 4:2:0 or monochrome SDR data. Explicit BT.709 primaries with BT.709 or sRGB transfer and BT.709/BT.470BG/SMPTE170M matrices are supported. Sequence metadata is checked independently of the codec string. Explicit PQ, HLG, wide-gamut primaries, linear transfer and ICtCp are unsupported. The H.264 packet path accepts AVC1/AVC3 baseline, main and high profile codes 66, 77 and 100 up to recognized level 5.2, using an AVC configuration record for length-prefixed data or parameter sets carried in Annex B data. It recognizes IDR access units as keys. SEI-only recovery points, high 4:4:4 and interlaced output remain outside verified support. VP8, VP9 and HEVC are unsupported. Configuration color overrides are declined where the native pipeline cannot apply them. Packet, picture and output-batch limits are recorded in packet.rs (16 MiB input, 4096 × 2304 picture pixels, 32 MiPixels converted per batch).

## Actual output and native guards

The browser film probe uses the ordinary pinned AV1 MP4, H.264 AVC MP4 and H.264 Annex B samples, each 10 frames decoded twice with a flush between runs. Across 60 output frames, candidate and Chrome matched presentation timestamps (including values above 32-bit range), durations and rotated/flipped display size 240 × 320. The unrotated LP coded size was 320 × 240 for all three. Chrome exposed 320 × 240 for AV1 and 320 × 258 with visible cropping for H.264. LP supplies packed sRGB RGBA; Chrome supplied I420 on these fixtures. The first sampled RGBA pixel was [255,0,254,255] on LP and [255,39,253,255] on Chrome for each fixture. This is a measured color difference. OpenH264 output in LP assumes limited-range BT.709 transfer and a matrix inferred from picture height; tagged or full-range H.264 accuracy remains unverified. The native AV1 path uses the sequence metadata and converts supported transfer characteristics to sRGB.
