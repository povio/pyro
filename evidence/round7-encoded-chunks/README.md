## Boundaries and controls

The initial f0396fd55 candidate delivered a chunk between different agent clusters where the pinned WPT requires rejection. It was withheld. The final build stamps each chunk with its originating cluster and checks the actual recipient before deserialization and before claiming transferred ports. Dedicated workers inherit their creator's identity, including data/blob URL workers. Window messaging and ports use messageerror for a failed recipient decode. In the pinned test all eight assertions now pass, including same-origin delivery, cross-cluster rejection, dedicated worker round trips, and shared/service worker exclusion. LP models origin-keyed clusters within a browsing context group; site-keyed Origin-Agent-Cluster opt-out remains unsupported. Current WebCodecs specifies storage rejection and copying internal slots; the cross-cluster prohibition is required by the pinned Chrome/WPT behavior and the standards question remains open. [WebCodecs serialization](https://w3c.github.io/webcodecs/#encodedvideochunk-serialization) · [Agent-cluster standards issue](https://github.com/w3c/webcodecs/issues/717)

The runner commands and three disjoint URL selections are included. export-accepted.py reads the frozen Chrome shard receipts from the benchmark cache and constructs page and named-assertion ledgers using the exact URL, original assertion name and one-based occurrence; null means unobserved. Each raw receipt is hashed in receipts.json. Native validation used cargo test --locked -j1 --profile wptiter -p pyro-webapi --test integration -- encoded_chunks_ structured_clone_ messaging_js:: with the pinned JSC and standard wptiter build variables. The JavaScript probes include the exact Window, IndexedDB, History and ordinary clone checks.
