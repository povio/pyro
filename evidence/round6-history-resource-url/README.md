# Referrer-policy and parser-time document URLs

On 354 pinned WPT URL variants LP increased from 282 to 354 fully passing pages and from 1,536 to 1,608 named passes (+72/−0). Chrome stable passed the same 354 pages and 1,608 names. Every gained name belongs to the first image or script request issued during parsing after a same-document history change. The adjacent 30-page history and base-URL guard produced identical LP page and named statuses, including one timeout on both builds. Chrome also had one timeout there.

The browser already updates document.URL immediately in history.pushState and history.replaceState. Resource events can be drained from parser execution before the normal frame synchronization checkpoint. The loader then used the previous frame URL as the referrer. The change synchronizes the affected frame's committed URL before processing its resource events, including deferred image/object work and frames sharing a DOM store. It obtains the fallback base from the current document to preserve inherited bases. The URL length threshold and the expected WPT results were untouched. [Source](https://github.com/povio/pyro/tree/75dcebe258a873acc7690e370496af6cfda8413f)

Same-origin HTTP probes measured the actual header received after replacing history at URL lengths 64, 4095, 4096 and 4097, across fetch, XHR, image, classic script, stylesheet and iframe. During parsing, both the top-level and nested-frame matrices went from 12/24 to 24/24. Chrome scored 24/24 on each. The later-task matrix was 24/24 on all three binaries. A separate nested-srcdoc requester check remained 27/27. The distribution includes the fixture source and raw request records. The HTTP origin and form of the referrer were generated by the local probe.

## Historical observations

The earlier census reported 157 pass-to-fail referrer-policy names on 64 pages, involving missing headers (119) or an invalid result URL (38). Of these names 105 passed and 52 failed in the matched 902fe811f census; 123 passed and 34 failed in the aa0268b47 loss-page rerun. historical.json preserves every name and observation. Those 64 pages are disjoint from the 354-page guard above.

On the frozen aa0268b47 binary, all four benign delayed-message controls received a child testharness timeout completion first and then a valid same-origin response with a referrer header. Observations cover url and srcdoc frames with ordinary and completion-only reporting. Chrome stable had previously shown this same ordering using the same fixture and WPT revision; its original receipt is included. The control establishes how an unfiltered first-message listener can fail while the actual request succeeds. The original census did not record all message payloads or network requests, so the 157 individual observations cannot all be attributed to this mechanism. None is counted in the 72 gains.

## Reproduction

WPT a421f2fea5eb7f91e0db399e44b0fb0779ee1603, CI arm64 JSC 0e0dd7038a7a-6f4649e395e0, macOS arm64, local Chrome stable 157.0.8103.80. LP control aa0268b479a6b463da16910b4b743cf38901d962 and candidate 75dcebe258a873acc7690e370496af6cfda8413f were run with four jobs. The public evidence uses the same-pin local WPT-profile Chrome census for the two WPT comparisons. Chrome history/referrer diagnostic probes were run locally; the older Chrome slow-message and nested-srcdoc receipts have their original provenance. [Frozen census](https://github.com/povio/pyro/tree/57a9450abdaa792dafae09f6e84d4236fa72a2ea/evidence/round6-noncss-census)

```sh
bun bench/wpt/run.mjs --wpt "$WPT" --kind testharness --dirs non-css --jobs 4 \
  --server wptserve --testdriver --http2 --generated-globals "$MANIFEST" \
  --manifest-inventory --measure-reviewed-skips --tests "$SELECTION" --bin "lp=$BIN" --out "$OUT"
```

Use history-guard.json or adjacent-guard.json for SELECTION. Named rows are URL, original name, occurrence, control, candidate and Chrome. Page rows are URL and each engine's page status, harness status and fully-passing flag in the same order. Missing observations are null. Summary count suffixes 0, 1 and 2 correspond to control, candidate and Chrome.

The additional inherited-base fixture makes two same-document fragment updates in each of an initial blank iframe and an srcdoc iframe. The candidate and Chrome kept the enclosing HTTP base on both updates and both relative XHRs reached the server with status 200. Source and raw records are in inherited-bases.tar.gz.
