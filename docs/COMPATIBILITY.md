# Known compatibility limits (runtime)

These are deliberate, documented deviations from browser behavior that come from JavaScriptCore's public/SPI
surface or from design choices in this rewrite. Each one is pinned by a test so a change in behavior is noticed.
TOS relevance is assessed from `tos-monorepo/apps/fe/e2e` usage; it is an assessment, not an E2E result.

| # | Limit | Pinned by | TOS relevance |
|---|---|---|---|
| 1 | **Window global shape.** Realms use JSC's default global object (the only one with module-loader support), whose `[[Prototype]]` is immutable. Window/EventTarget members are own properties of the global. `window instanceof Window/EventTarget` holds via `Symbol.hasInstance`, and the tag is `[object Window]`. But `Object.getPrototypeOf(window)` is `Object.prototype`, and patching `EventTarget.prototype.addEventListener` does not change `window.addEventListener`. | `lp-js` `global_object_backed_by_host_class` | Low for React apps. Higher for zone.js-style global patching, which TOS does not use. Playwright's injected scripts read but do not patch window prototypes. |
| 2 | **Termination through native frames.** The C API cannot rethrow JSC's uncatchable termination. When native code sees it, it rethrows and re-arms the watchdog, so JS that catches the termination is terminated again within about 50 ms. The call returns `JsError::Terminated`. | `nested_termination_cannot_be_swallowed`, `termination_ignored_by_native_code_still_terminates` | Only affects `Runtime.terminateExecution` and timeouts. |
| 3 | **Root-relative module URLs (system framework only).** JSC resolves `"/x.js"` to `file:///x.js`. The runtime fetches it from the page origin, but the module's `import.meta.url` is `file:///x.js`. An explicit `file:///…` import from an http page is also fetched from the page origin. | `es_modules_through_fetcher`, `module_url_remapping_only_touches_root_relative_file_urls` | Vite production builds import chunks relatively (`./chunk.js`), so they are unaffected. Code that inspects `import.meta.url` for root-relative imports is affected. |
| 4 | **Inline module scripts** are registered as `<document URL>#inline-module-N`, because JSC's registry is keyed by URL. `import.meta.url` carries that fragment; relative resolution is unchanged. | `lp-browser` `script_ordering_*` (inline module) | Vite's `index.html` uses an external `type=module` entry, so it is unaffected. |
| 5 | **Deferred modules block DCL until fully evaluated.** JSC fetches a module graph during evaluation, so `DOMContentLoaded` waits for each deferred module's evaluation promise, including top-level await. Browsers wait only for graph fetching. | `script_ordering_with_static_loader` (ext-module with `await 0` precedes DCL) | DCL may fire later than in Chromium if the entry module awaits network work at top level. `load` is unaffected in practice. |
| 6 | **No timer nesting clamp in workers.** Window timers follow the HTML nesting clamp (4 ms past level 5); nested `setTimeout(0)` chains in a dedicated worker do not get it. | `lp-browser` `nested_timers_are_clamped_to_4ms_past_level_5` | Makes worker polling loops faster. Code that depends on the clamp's timing is rare. |
| 7 | **Import maps cover parser-inserted inline maps only, on the patched JavaScriptCore.** Maps added by script or `document.write` and external maps are ignored; `integrity` is parsed but not enforced; rejected maps report an exception but fire no `error` event. The system framework fallback ignores import maps with a console warning. | `import_maps_map_bare_specifiers`, `import_maps_resolve_specifiers_like_the_html_spec` | The Vite build does not use import maps. |
| 8 | **ES modules only on macOS.** The module loader uses JSC's Objective-C SPI. Linux is not supported. | `Capabilities::modules` | The TOS Linux CI lane stays on upstream Lightpanda until ESM support is implemented and verified there. |
| 9 | **Interface objects are Proxies; members are installed on first use.** Interface objects (`Node`, `HTMLElement`, …) are Proxies over the real constructors, and their prototype objects, prototype and static members (and embedder additions such as unscopables) are made on first use. That step defines members rather than assigning them and reads only its own tables, so a page that changed `Object.prototype` or `Array.prototype` before the first use gets the same interfaces, and a first use that fails part way (stack overflow, termination) is completed by the next one. Descriptors, identities and inheritance match eager installation, also when the interface belongs to a disposed realm and is reached from another realm. In that case native calls throw `Execution context was destroyed.`, as before. Two differences remain: `Function.prototype.toString(Node)` reports `function () { [native code] }` instead of internal helper source, and property operations on interface objects (including `instanceof`) pay a proxy-trap cost. | `lp-js` `tests/lazy_interfaces.rs` | The trap cost applies only to interface objects, not to prototypes or instances. Its CPU effect is measured only by the local HTTP harness, which includes it. |
