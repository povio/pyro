# Automatic box heights in synthetic layout

The renderless layout places nodes5px apart in tree order. Previously an automatic parent height summed only direct-child fallback/declared sizes, ignoring child offsets and nested automatic boxes. In a selectable wrapper containing three nested nodes, the button could begin15px below a5px parent. When the button inherited pointer-events:none, its center missed every eligible wrapper and hit BODY or another ancestor.

Automatic non-root height now also encloses visible normal-flow child boxes at those existing positions. Explicit heights, positions, width approximations and hit-test traversal stay unchanged. The additional extent excludes absolutely positioned/floated children; existing direct-child/text measurement remains a lower bound. Explicit clipping, real CSS block/flex/table layout and stacking remain separate limitations. This change is not proof of full-page TOS causation or HBL placement correctness.

An iterative subtree pass and bottom-up calculation avoid recursive Rust traversal. Results are cached by the existing DOM/style/focus/hover observation stamp; repeated rectangle queries reuse child heights. Scroll dimensions remain at least their client dimensions. A hidden/class/mutation/removal regression verifies invalidation. The old marquee test now uses an explicit viewport height: an automatic parent correctly grows with cloned children and cannot be outgrown by that loop.

Validation before browser integration: two new native regressions failed before the repair; three regressions pass after. DOM+WebAPI suites and strict crate clippy pass. Native timing uses the retained ignored automatic_height_timing_diagnostic on4004nodes, same host/debug build: single cold query3315→7330us,1000 repeated queries893779→436949us,10 mutation+query cycles13947→68192us. This sample shows a rebuild cost tradeoff, not a broad CPU/speed improvement. Browser/static/TOS validation and release evidence are recorded separately when completed.
