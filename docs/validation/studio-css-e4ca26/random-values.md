# CSS random values and explicit custom-property transitions

Studio compares LP 0.0.17 (JSC `0e0dd7038a7a-6f4649e395e0`) with Chrome stable 158.0.8127.37 at WPT `a421f2fea5eb7f91e0db399e44b0fb0779ee1603`. Main: 8,082 URLs, six workers, `wptserve` and testdriver. Supplemental: 41 worker-global URLs compared separately. The other 39 URLs are withheld, not passes. Each `difference` stores both sides of the strict page, passing named assertion, and observed-name differences. Each `outcomes` stores per-URL harness status and named results.

`randcontext` vs `450012da`: 5,660 strict pages (+3/-0) and 181,130 passing names (+256/-1). No missing URLs or change to the observed-name set. LP/Chrome exclusive: 276/1,566 pages; 5,897/7,730 names. The 59-URL random and control cohort reproduces every gain and loss. Supplement stays 27 pages / 577 passing names vs Chrome 35 / 619. The original diagnostic build lost eight more assertions because it admitted explicit random keys in query contexts and used the spelling of a property alias in its cache key. Those eight recover with declaration-context checking and unaliased property keys. Context restrictions follow the pinned interoperable tests; CSSWG issue 10982 remains open. One registered-number transition at progress -0.5 changes from an accidental initial-value pass to displaying its final value; neither is a correctly sampled transition.
