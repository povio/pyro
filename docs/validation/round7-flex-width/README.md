# Non-scrolling flex scrollWidth: shared horizontal start

Parent `e090242d6c73f7f9e9bded0b045f3489fb35f0bd`; source `8f5ac0a524e35a926aed54fc3f5a568361ffd01b`. Non-scrollers retain both edges of overflow but have no reversed scroll-origin flag. When the writing mode starts on the right and flex main/cross start on the horizontal axis agrees, measure from the right padding edge. For example, horizontal RTL row with negative margins, visible overflow: 196 → 184 CSS px, also 184 in Chrome. No changes to flex layout, propagation, clipping, real scrolling, offsets, containment, or vertical measurement.

[CSSOM View](https://drafts.csswg.org/cssom-view/#scrolling-area) defines overflow directions by writing mode. The matched negative-margin WPT additionally flips direction for reversed flex axes. Chrome does not meet all those expectations. This patch fixes the undisputed cases, retaining parent readings when horizontal flex and writing-mode starts disagree. It does not claim to resolve reverse-axis interop.
