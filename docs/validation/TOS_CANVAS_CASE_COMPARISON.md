# TOS 9-case batch: rewrite, upstream and Chromium comparison, 2026-10-17

The [batch 1](TOS_COVERAGE_BATCH_1.md) selection was rerun unchanged after the
WebAPI gaps it exposed were fixed. The rewrite now passes 8/9 cases and upstream
Lightpanda also passes 8/9. Both fail the same case at the same assertion. Native
Chromium, run on that case's spec file, passes 2/3 and fails that case at the same
assertion.

No rewrite-specific cause is established for the shared failure. A fixture or
environment cause at this TOS commit is likely but not proven: the root cause has
not been identified. No test, helper, auth, manifest, data or timeout was changed
to investigate it.

| Upstream, routed | `lpup9-1017-140516` | upstream `2ad38773fd674d3c9cea26a263b814ee46f6ba84` | 8 | 1 |
| Upstream, routed, navigation file only | `lpupnav-1017-140350` | same upstream binary | 2 | 1 |
| Chromium, direct, navigation file only | `lpchrnav-1017-140905` | Playwright 1.59.1 chromium-headless-shell 147.0.7727.15 (rev 1217) | 2 | 1 |

The shared failure is "Platform navigation FE E2E > switches from Finances back to
filtered Positions without leaving the previous module rendered"
(`e2e/platform/navigation.e2e.ts:74`).
- In every lane, the URL, title and "Incoming Invoices link absent" assertions
  after returning to Logistics pass.
- `expect(getLastCanvasTable(page)).toBeVisible()` then times out after 10s. The
  locator is `[role="grid"][aria-label="Data table"], .x-canvas-table` (visible,
  last), and Playwright reports "element(s) not found".
- The other eight cases pass in both routed Lightpanda lanes:
  - four Employees list/sort/search/filter cases;
  - two Office autosave cases;
  - the calendar route;
  - the platform-root redirect.

The Chromium lane differs in setup from the routed Lightpanda lanes:
- It used `playwright.e2e.config.ts` directly. The routed config's Chromium
  project runs only cases *outside* the manifest.
- Its `openRoute` does a cold `page.goto` deep link, not the pushState/PopStateEvent
  router bootstrap.
- Activation uses native clicks, not synthetic DOM events.

The same assertion failing on both paths is consistent with a cause that is not
specific to any engine or route setup. It does not prove one. Separate DOM probes
on the rewrite and on Chromium also found no matching grid or canvas table on that
route. Those probes ran in a separate diagnostic worktree with added diagnostic
specs and are not part of this measurement.
